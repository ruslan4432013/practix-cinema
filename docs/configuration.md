# Конфигурация (переменные окружения)

Корневой `.env` (шаблон — `.env.example`) драйвит все сервисы compose. Ключевые группы:

| Группа | Переменные |
|--------|-----------|
| **Rate limit** (Auth) | `RATE_LIMIT_ENABLED`, `RATE_LIMIT_TIMES` (20), `RATE_LIMIT_SECONDS` (60) |
| **Трассировка** | `OTEL_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://jaeger:4318` (per-service `OTEL_SERVICE_NAME` задаётся в compose) |
| **Сбор ошибок** | `SENTRY_ENABLED`, `SENTRY_DSN`, `SENTRY_ENVIRONMENT`, `SENTRY_RELEASE`, `SENTRY_SAMPLE_RATE`, `SENTRY_SEND_DEFAULT_PII`. Один DSN на все сервисы, различает их тег `service` (берётся из `OTEL_SERVICE_NAME`) |
| **GlitchTip** | `GLITCHTIP_SECRET_KEY` (**обязательно заменить**), `GLITCHTIP_DOMAIN`, `GLITCHTIP_HOST_PORT`, `GLITCHTIP_ENABLE_OPEN_USER_REGISTRATION`, `GLITCHTIP_POSTGRES_*`, `GLITCHTIP_EMAIL_URL` |
| **Логи** | `LOG_LEVEL`, `LOG_JSON` (все сервисы). ELK: `ELASTIC_LOGS_HOST_PORT` (9210), `KIBANA_HOST_PORT` (5601), `LOGSTASH_BEATS_HOST_PORT` (5044), `ES_LOGS_JAVA_OPTS`, `LS_JAVA_OPTS`, `KIBANA_ENCRYPTION_KEY`, `COMPOSE_PROJECT_NAME` (по нему Filebeat отсеивает контейнеры чужих проектов) |
| **Интеграция Auth** (Movies API / Django) | `AUTHJWT_SECRET_KEY`, `AUTH_API_URL=http://auth:8000`, `AUTH_REQUEST_TIMEOUT` / `AUTH_API_TIMEOUT=2.0`, `AUTH_API_MAX_ATTEMPTS=3` |
| **OAuth** | `OAUTH_ENABLED=False`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI=http://localhost/api/v1/oauth/yandex/callback` |
| **PostgreSQL (фильмы)** | `POSTGRES_HOST` / `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` |
| **PostgreSQL (Auth)** | `AUTH_POSTGRES_HOST` / `AUTH_POSTGRES_PORT` / `AUTH_POSTGRES_DB` / `AUTH_POSTGRES_USER` / `AUTH_POSTGRES_PASSWORD` |
| **Elasticsearch / Redis** | `ELASTIC_HOST` / `ELASTIC_PORT`, `REDIS_HOST` / `REDIS_PORT` |
| **Django superuser** | `DJANGO_SUPERUSER_USERNAME` / `DJANGO_SUPERUSER_PASSWORD` / `DJANGO_SUPERUSER_EMAIL` |
| **Kafka** | `KAFKA_CLUSTER_ID` (одинаковый у всех узлов), `KAFKA_BOOTSTRAP_SERVERS`, `KAFKA_TOPIC_*` |
| **Analytics Collector** | `UGC_ENV` (`prod` включает обязательные проверки безопасности), `UGC_REDIS_DB=1`, `UGC_FALLBACK_*` (буфер деградации), `UGC_MAX_BODY_BYTES` / `UGC_MAX_BATCH_SIZE`, `UGC_RATE_LIMIT_*` (600/60 с), `UGC_IP_HASH_SALT` (**обязательно заменить в проде**), `UGC_CORS_ALLOW_ORIGINS` |
| **ClickHouse** | `CH_CLUSTER=ugc_cluster`, `CH_DATABASE=ugc`, `CH_USER` / `CH_PASSWORD` (**обязательно заменить в проде**), `CH_HOSTS` (по одному узлу на шард — это координаторы вставки, а не реплики), `CH_INSERT_QUORUM=2` (аналог acks=all + ISR=2: отказ реплики становится лагом, а не потерей), `CH_RETRY_*`, `CH_SEND_RECEIVE_TIMEOUT` |
| **ETL ClickHouse** | `ETL_CONSUMER_GROUP`, `ETL_FLUSH_INTERVAL` / `ETL_BATCH_MAX_ROWS` / `ETL_BATCH_MAX_BYTES` (три порога закрытия пачки), `ETL_FETCH_MAX_BYTES` / `ETL_MAX_PARTITION_FETCH_BYTES` (**реальные рычаги потребления памяти**), `ETL_MAX_SCHEMA_VERSION`, `ETL_METRICS_PORT`, `ETL_TRACEMALLOC_*`, `ETL_RSS_WARN_MB` |
| **Grafana** | `GF_SECURITY_ADMIN_PASSWORD` |
| **Нотификации** | `NOTIFY_ENV`, `NOTIFY_SECRET_KEY` / `NOTIFY_DEBUG` / `NOTIFY_ALLOWED_HOSTS` / `NOTIFY_CSRF_TRUSTED_ORIGINS`, `NOTIFY_POSTGRES_*` (своя база), `NOTIFY_AMQP_URL` / `NOTIFY_AMQP_HEARTBEAT` (больше самой долгой блокирующей операции воркера — иначе канал рвётся посреди отправки) / `NOTIFY_AMQP_SOCKET_TIMEOUT` / `NOTIFY_AMQP_STACK_TIMEOUT` (дедлайн ПОДКЛЮЧЕНИЯ, не путать с heartbeat: без него ожидание TCP отмеряет ядро, а планировщик однопоточный — за публикацией стоят тик расписаний, чистки и веер) / `NOTIFY_PREFETCH_COUNT` / `NOTIFY_RETRY_TTL_MS` / `NOTIFY_MAX_ATTEMPTS`, `NOTIFY_SMTP_*` (включая `NOTIFY_SMTP_RATE_PER_SECOND` — темп, которым не роняют почтовый сервер, / `NOTIFY_SMTP_RATE_SCOPE` — этот темп считается НА СЕРВИС через общий слот в Redis ядра, потому что попроцессный лимит умножался бы на число реплик отправляющего воркера; `process` возвращает прежнее попроцессное поведение / `NOTIFY_SMTP_RATE_MAX_WAIT` — потолок ожидания слота, при превышении получатель уезжает в ярус повторов), `NOTIFY_FANOUT_*` / `NOTIFY_PUBLISH_SLEEP` (занижение пикового RPS на запись в брокер), `NOTIFY_BUILD_MESSAGE_BATCH` (получателей в одном сообщении с ГОТОВЫМИ телами писем — поэтому меньше веерной пачки) / `NOTIFY_BUILDER_LOOKUP_BATCH` / `NOTIFY_BUILDER_SLEEP` (две ручки нагрузки на Auth: размер пачки резолва и пауза между пачками) / `NOTIFY_DIRECTORY_CACHE_TTL` / `NOTIFY_DIRECTORY_CACHE_MAX` (кеш личных данных в памяти сборщика; 0 выключает) / `NOTIFY_RETRY_BUILD_TTL_MS` / `NOTIFY_BUILD_MAX_ATTEMPTS` (второй ярус повтора: отказ Auth длиннее икоты почтового сервера) / `NOTIFY_AUTH_RETRY_AFTER_MAX` (потолок на Retry-After при 429), `NOTIFY_SCHEDULER_TICK_SECONDS` / `NOTIFY_OUTBOX_MAX_ATTEMPTS` (потолок попыток публикации ОДНОЙ строки outbox — страховка от отказов, которые ожиданием не лечатся: без него такая строка встала бы в голову выборки по времени создания и остановила все рассылки) / `NOTIFY_OUTBOX_CLAIM_TTL_SECONDS` (аренда захваченной строки; публикация идёт ВНЕ транзакции, и две реплики планировщика разводит именно она — **обязана быть больше 2 × `NOTIFY_AMQP_HEARTBEAT`**, иначе аренда истекает, пока первая реплика ещё внутри `basic_publish`, и дубль публикации становится штатным; проверяется на старте) / `NOTIFY_OUTBOX_RETRY_START` / `NOTIFY_OUTBOX_RETRY_MAX` (отсрочка после неудачной публикации: без неё бюджет попыток мерил не выносливость, а секунды — слив крутится раз в секунду) / `NOTIFY_OUTBOX_ALERT_PENDING` (порог, после которого `/health/ready` отвечает `degraded`) / `NOTIFY_ATTEMPTS_RETENTION_DAYS` (журнал попыток чистится тем же часовым тиком, что и лента) / `NOTIFY_REPORT_TTL_MS` (срок жизни отчётного события — задан НА СООБЩЕНИИ, потому что очередь без консьюмера уже объявлена и новые аргументы дали бы 406), `NOTIFY_QUIET_HOURS_*` (в таймзоне получателя; отсрочка по ним возвращается в очередь с НЕИЗМЕНЁННЫМ счётчиком попыток, иначе ночное окно съедало бы `NOTIFY_MAX_ATTEMPTS` за минуты), `NOTIFY_TEMPLATE_MAX_BYTES` / `NOTIFY_RENDER_TIMEOUT_SECONDS`, `NOTIFY_INTAKE_TOKEN` (**обязательно заменить**), `NOTIFY_AUTH_SERVICE_LOGIN` / `NOTIFY_AUTH_SERVICE_PASSWORD` (сервисная учётка в Auth), `NOTIFY_SUPERUSER_*` (вход в панель), `NOTIFY_FREEFORM_RAW_TEXT_ENABLED` (сырой текст в ручке `/messages` валидируется рендером в отдельном процессе — то есть процесс на запрос; выключение оставляет только путь через `template_id`), `NOTIFY_INBOX_*` / `NOTIFY_CABINET_*` (лента личного кабинета: превью вместо тела письма, срок хранения, размер страницы), `AUTHJWT_SECRET_KEY` (**обязательно заменить** — общий ключ стенда, которым подписывает Auth; иначе токен кабинета можно подделать) / `NOTIFY_JWT_ALGORITHM` / `NOTIFY_JWT_LEEWAY_SECONDS`, `NOTIFY_DENYLIST_ENABLED` / `NOTIFY_DENYLIST_ON_ERROR` (`deny` — лента тем, о которых человеку писали, не открывается по токену, про который неизвестно, жив ли он) / `AUTH_REDIS_*` / `NOTIFY_REDIS_TIMEOUT` (денилист читается там же, где его пишет Auth) |
| **Websocket-шлюз** (`apps/notifications-ws/`) | `NOTIFY_WS_*` (префикс свой: голый `NOTIFY_` принадлежит панели и воркерам, а корневой `.env` читают все сразу). `NOTIFY_WS_TICKET_TTL` — срок жизни одноразового ticket'а; `NOTIFY_WS_ALLOWED_ORIGINS` — единственный барьер против CSWSH, потому что у websocket нет same-origin policy; `NOTIFY_WS_REVALIDATE_SECONDS` — период перепроверки отзыва (без него сокет пережил бы logout); `NOTIFY_WS_RECONNECT_*` и `NOTIFY_WS_PROBE_INTERVAL` — политика деградации, которую шлюз ОБЪЯВЛЯЕТ клиенту вместе с ticket'ом, чтобы тайминги фронтенда не были зашиты в JavaScript. Без префикса, потому что описывают чужие сущности: `AUTHJWT_SECRET_KEY`, `AUTH_REDIS_*`, `NOTIFY_AMQP_URL` |
| **Сокращение ссылок** (`apps/link-shortener/`) | `SHORTENER_*` (префикс свой: `UGC_`, `UGC_API_`, `NOTIFY_`, `NOTIFY_WS_`, `ETL_` и `CH_` заняты, а корневой `.env` читают все контейнеры). `SHORTENER_POSTGRES_*` — своя база; `SHORTENER_PUBLIC_BASE_URL` / `SHORTENER_REDIRECT_PATH` — ВНЕШНИЙ адрес ссылки (она уезжает в письмо и открывается с телефона), путь обязан совпадать с `location ^~ /s/` в nginx; `SHORTENER_CODE_LENGTH` (7 — 62⁷ вариантов: короче нельзя, ссылка подтверждает адрес почты и перечислимый код означал бы подтверждение чужого ящика перебором) / `SHORTENER_CODE_MAX_ATTEMPTS`; `SHORTENER_DEFAULT_TTL_HOURS` / `SHORTENER_MAX_TTL_HOURS`; **`SHORTENER_ALLOWED_REDIRECT_HOSTS`** — белый список хостов редиректа, единственная защита от открытого редиректа (пустое значение = фишинг с нашим доменом в адресной строке жертвы); `SHORTENER_INTERNAL_TOKEN` (**обязательно заменить**) — служебный токен ручки создания ссылок; `SHORTENER_AUTH_*` — учётка с УЗКОЙ ролью `email-confirmer`, которой сервис помечает адрес подтверждённым; `SHORTENER_PURGE_BATCH` / `SHORTENER_PURGE_SLEEP` — размер пачки и пауза между пачками у `cli purge`: уборка удаляет протухшие строки порциями, потому что один DELETE на всю таблицу — это длинная транзакция, держащая блокировки на строках, по которым в это же время идёт счётчик визитов горячего редиректа (и разом раздувающая WAL) |
| **Ссылка подтверждения в письме** (нотификации) | `NOTIFY_SHORTENER_API_URL`, `NOTIFY_SHORTENER_INTERNAL_TOKEN` (**та же строка, что `SHORTENER_INTERNAL_TOKEN`** — две стороны одного секрета), `NOTIFY_SHORTENER_TIMEOUT` / `NOTIFY_SHORTENER_MAX_ATTEMPTS`, `NOTIFY_CONFIRM_REDIRECT_URL` (запасное значение, когда поле кампании пусто; по умолчанию главная страница кинотеатра), `NOTIFY_CONFIRM_LINK_TTL_HOURS` (отсчитывается от СБОРКИ письма, а не от регистрации — иначе письмо, отложенное тихими часами, приезжало бы с мёртвой ссылкой) |
| **Продюсеры событий** (Auth, контентная админка) | `NOTIFY_EVENTS_ENABLED` (**выключено по умолчанию**: без профиля `notifications` такого хоста нет в сети, и включённый продюсер резолвил бы его на каждой регистрации), `NOTIFY_API_URL`, `NOTIFY_INTAKE_TOKEN` (тот же секрет и то же имя, что у нотификаций — ротация в одном месте), `NOTIFY_EVENT_TIMEOUT` / `NOTIFY_EVENT_MAX_ATTEMPTS` (повторы только на 5xx и на обрыве; провал доставки события никогда не ломает регистрацию или сохранение фильма) |

Все публикуемые порты — тоже переменные (`NGINX_HOST_PORT`, `JAEGER_UI_HOST_PORT`
и прочие), поэтому адреса из [быстрого старта](quickstart.md) меняются вместе с
ними. Состав хранилищ и портов по умолчанию — в [`architecture.md`](architecture.md).
