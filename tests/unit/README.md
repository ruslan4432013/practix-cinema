# Юнит-тесты

Тесты чистых функций — без Kafka, Redis, Postgres и Docker.

## Зачем они появились

Весь набор в репозитории был функциональным. Для интеграционных путей это
правильно, но часть логики проверялась дороже, чем нужно: чтобы убедиться, что
`blake2b` даёт стабильный хеш или что `video_progress` уходит в свой топик,
поднимался кластер Kafka и Redis. Десятки секунд там, где хватило бы
миллисекунд, — и, как следствие, цикл обратной связи, который никто не гоняет
на каждое сохранение файла.

Юнит-тесты **не заменяют** функциональные: партиционирование, заголовки
сообщений и поведение при отказе брокера проверяются только на живой
инфраструктуре.

## Что покрыто

| Файл | Что проверяет |
|------|---------------|
| `test_privacy.py` | Хеширование IP, усечение и разбор User-Agent, выбор адреса клиента и доверие к `X-Forwarded-For` (включая подделку левых элементов) |
| `test_broker_health.py` | Разделение отказов продюсера: ошибка записи не переводит брокер в degraded, отказ соединения переводит |
| `test_events.py` | Приоритет ключа партиционирования, round-trip `KafkaRecord.to_dict()` / `from_dict()` |
| `test_topics.py` | Соответствие каждого `EventType` топику; полнота маппинга |
| `test_requests_validation.py` | Валидаторы входных DTO: схемы URL, плоскость `properties`, расхождение часов, правдоподобность длительностей |

## Запуск

```bash
PYTHONPATH=analytics_collector/src UGC_ENV=test pytest tests/unit -v
```

`PYTHONPATH` нужен по той же причине, что и в остальных сервисах: пакеты
импортируются от корня `src` (`from core.privacy import ...`), а не с префиксом
пакета. `conftest.py` подставляет путь сам, если переменная не задана, — чтобы
`pytest tests/unit` работал и без обёртки.
